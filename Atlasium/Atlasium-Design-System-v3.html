Atlasium Design System
Overview & extension guide

One set of color, type and component tokens for building consistent interfaces across marketing pages, dashboards and product UI. The rules below are strong defaults, not a cage — bend them with intention when the content calls for it.

§1 — Philosophy: consistent, not rigid

A design system earns trust by making the obvious choice easy and the right choice consistent — not by making every screen look identical. Split every rule below into two piles: what has to stay fixed for the whole product to feel like one thing, and what's free to change per page, per team, per feature.

✓ Foundation — keep consistent
What gives the system its identity
— All CSS color tokens (--bg, --surface, --accent…)
— Typefaces: Inter for UI · DM Mono for code, numbers, mono data
— Teal→indigo gradient, used once per view
— Badge formula: bg 12% · border 30% · text 100%
— Border-radius scale: 2 · 4 · 8 · 12 · 16 · 999px
— Elevation via surface layering, not box-shadow
— No entrance animation beyond skeleton shimmer
— No hardcoded hex colors
✦ Flexible — adapt per product
What can flex to fit the context
— Badge copy doesn't need to match one domain (Available → Active, etc.)
— Card layout: add or drop header/body/footer freely
— Semantic colors: use --success/danger/warning/info wherever they fit
— Grid columns: shape them to the content, not a fixed 2fr 1fr 1fr
— Hero sections don't require a search bar
— Max-width can grow (960px → 1200px for a dashboard, full-bleed for landing)
— Gradient text can appear on any heading, not only the hero
— New components (modal, tabs, sidebar…) are welcome as long as they're built on tokens
Core rule: tokens are the contract, implementation is free. As long as you reach for a CSS variable instead of a hardcoded hex, you're "inside" the system. Every new component only has to pass one test: does it work in both dark and light mode? If a documented rule ever blocks the best answer for real content, override it on purpose and leave a note explaining why — that makes a healthier system than one nobody dares to bend.

✦ New

Build your product,
faster than before.

A short line on the product's value. Two lines max, under 25 words.

Background: place the hero directly on var(--bg) — skip the card/surface wrapper and the hero-grid overlay.
Gradient text: one phrase in the heading · no other gradient in the same section.

5D — Guidelines, not decrees

These are the defaults that keep the product feeling like one thing. Reach for them first. If a specific screen genuinely needs something different, break the rule on purpose and note why — a documented exception is healthy; an accidental one is drift.

• Reach for a CSS variable before a hardcoded hex — it's what keeps dark and light mode in sync automatically.
• Save the gradient for one moment per view — scarcity is what makes it feel intentional.
• Keep 999px border-radius for badges and chips; on a button it reads as a pill, not a call to action.
• Build elevation with surface layering rather than box-shadow, to match the flat, layered feel of the rest of the kit.
• Skip entrance and scroll animation — skeleton shimmer is the one motion in the system, so it stays legible as "loading" rather than decoration.
• Wrap content in a surface before placing it on --bg, except for the hero, which is the deliberate exception.
• Give badges a tinted background instead of a solid fill, so they stay legible in both themes.
• Let a gradient wrap a full phrase in a heading, not a single word — an accented word reads as a typo more than emphasis.

Knowing when to step outside the system
Consistency is a means, not the goal
A one-off landing page, an experiment, or a piece of content that needs its own visual voice doesn't have to wear this system. Use it as the default for anything that lives inside the product — settings, dashboards, transactional pages — and treat it as optional for anything that exists to make a single, memorable impression. When you do deviate, keep the type and spacing scale as a quiet baseline; that's usually enough to still feel like the same company without forcing the same components.
